# Kubernetes Guideline — mono-ticket

> Your bridge from `docker-compose` to Kubernetes. Read this first.

---

## 1. Docker Compose → Kubernetes: What Changed?

| Docker Compose Concept | Kubernetes Equivalent | Manifest File |
|:---|:---|:---|
| `services:` | **Deployment** + **Service** | `03-mongodb.yaml`, `04-ticket-api.yaml`, `05-ticket-admin.yaml` |
| `volumes:` | **PersistentVolumeClaim** (PVC) | `03-mongodb.yaml` |
| `networks:` | **Namespace** + **ClusterIP Services** | `00-namespace.yaml` |
| `ports: "8000:8000"` | **Service** + **Ingress** | `06-ingress.yaml` |
| `environment:` / `env_file:` | **ConfigMap** + **Secret** | `01-configmap.yaml`, `02-secrets.yaml` |
| `depends_on:` | **Startup probes** + manual deploy order | Deploy DB before API |
| `restart: unless-stopped` | `restartPolicy: Always` (K8s default) | Built-in |
| `healthcheck:` | `readinessProbe` + `livenessProbe` + `startupProbe` | In each Deployment |
| `build:` | `docker build && docker push` separately | Done on your local machine |
| `container_name:` | Pod names (auto-generated by Deployment) | K8s manages this |
| `docker-compose up -d` | `kubectl apply -f k8s/` | One command to deploy all |
| `docker-compose down` | `kubectl delete -f k8s/` | One command to tear down |
| `docker-compose logs` | `kubectl logs -f deployment/<name>` | Per-deployment logs |

## 2. File Structure & Apply Order

```
k8s/
├── 00-namespace.yaml        # Isolated environment (ticket-prod)
├── 01-configmap.yaml        # Non-sensitive env vars (SERVER_PORT, SPRING_PROFILES_ACTIVE)
├── 02-secrets.example.yaml  # Template for sensitive credentials (copy to 02-secrets.yaml)
├── 03-mongodb.yaml          # Database: PVC (5Gi) + Deployment + Service + Init ConfigMap
├── 04-ticket-api.yaml       # Spring Boot API: Deployment + Service + JVM limits
├── 05-ticket-admin.yaml     # Vue.js SPA: Nginx ConfigMap + Deployment + Service
├── 06-ingress.yaml          # External routing rules (Traefik Ingress + HTTPS redirect)
├── 07-cluster-issuer.yaml   # Auto SSL certificate from Let's Encrypt (Traefik ACME solver)
├── 08-mongodb-network-policy.yaml # Zero-trust NetworkPolicy (only ticket-api can access DB)
├── deploy.sh                # Production deployment automation CLI script
└── k8s_guideline.md         # ← You are here
```

**Deploy order matters for first-time setup:**
```bash
kubectl apply -f k8s/00-namespace.yaml              # 1. Namespace first
kubectl apply -f k8s/01-configmap.yaml              # 2. Config before apps
# 3. Create secrets (from template):
cp k8s/02-secrets.example.yaml k8s/02-secrets.yaml
# (edit k8s/02-secrets.yaml with actual credentials)
kubectl apply -f k8s/02-secrets.yaml
kubectl apply -f k8s/03-mongodb.yaml                # 4. Database before API
kubectl apply -f k8s/08-mongodb-network-policy.yaml # 5. DB NetworkPolicy isolation
# Wait for MongoDB to be ready:
kubectl wait --for=condition=ready pod -l app.kubernetes.io/name=mongodb -n ticket-prod --timeout=120s
kubectl apply -f k8s/04-ticket-api.yaml             # 6. API after DB is ready
kubectl apply -f k8s/05-ticket-admin.yaml           # 7. Frontend
kubectl apply -f k8s/07-cluster-issuer.yaml         # 8. SSL issuer
kubectl apply -f k8s/06-ingress.yaml                # 9. Ingress routes (last)
```

**Or automated deployment via script:**
```bash
./k8s/deploy.sh deploy
```

### Two paths to the API:
1. **Through the frontend** — User visits `yourdomain.com`, Vue app makes `/api/*` calls → Nginx inside the frontend pod proxies to `ticket-api-svc`
2. **Direct API access** — `api.yourdomain.com` goes directly to `ticket-api-svc` via Ingress (useful for mobile apps, Postman, webhooks)

## 4. Key Kubernetes Concepts (Quick Reference)

| Concept | What It Is | Docker Compose Equivalent |
|:---|:---|:---|
| **Pod** | Smallest deployable unit. Contains 1+ containers. | A running container |
| **Deployment** | Manages pods: creates, updates, scales, self-heals | `services:` definition |
| **Service (ClusterIP)** | Internal DNS name + load balancer for pods | Service name in compose network |
| **ConfigMap** | Key-value config injected as env vars or files | `environment:` in compose |
| **Secret** | Like ConfigMap but for sensitive data (base64 encoded) | `.env` file |
| **PersistentVolumeClaim** | Request for persistent storage | `volumes:` in compose |
| **Ingress** | External HTTP/HTTPS routing rules | External nginx reverse proxy |
| **Namespace** | Isolation boundary for resources | Docker network (but stronger) |
| **Probe (readiness)** | "Is this pod ready to receive traffic?" | `healthcheck:` |
| **Probe (liveness)** | "Is this pod still alive? Restart if not." | `restart: unless-stopped` |
| **Probe (startup)** | "Has this pod finished starting?" | `start_period` in healthcheck |

## 5. How to Customize

### Change Docker image names
Edit the `image:` field in:
- [04-ticket-api.yaml](./04-ticket-api.yaml) — line `image: yourdockeruser/ticket-api:latest`
- [05-ticket-admin.yaml](./05-ticket-admin.yaml) — line `image: yourdockeruser/ticket-admin:latest`

### Set real secrets
Edit [02-secrets.yaml](./02-secrets.yaml) — replace all `CHANGE_ME` values with your actual credentials.

### Change domain names
Edit [06-ingress.yaml](./06-ingress.yaml) — replace all `yourdomain.com` with your actual domain.
Edit [07-cluster-issuer.yaml](./07-cluster-issuer.yaml) — replace the email address.

### Adjust resource limits
If you upgrade to a larger instance (e.g., `t3.small` with 2GB RAM), you can increase:
- MongoDB limits in `03-mongodb.yaml`
- JVM heap in `04-ticket-api.yaml` (`-Xmx256m` → `-Xmx512m`)
- Overall pod limits

### Remove image pull secrets
If your Docker images are **public**, remove these lines from `04-ticket-api.yaml` and `05-ticket-admin.yaml`:
```yaml
      imagePullSecrets:
        - name: regcred
```

## 7. Common Commands Cheat Sheet

### Check status
```bash
kubectl get pods -n ticket-prod                    # List all pods
kubectl get svc -n ticket-prod                     # List all services
kubectl get ingress -n ticket-prod                 # Check routing rules
kubectl get pvc -n ticket-prod                     # Check storage claims
kubectl get certificate -n ticket-prod             # Check SSL cert status
```

### View logs
```bash
kubectl logs -f deployment/ticket-api -n ticket-prod       # API logs (live)
kubectl logs -f deployment/ticket-admin -n ticket-prod     # Frontend logs
kubectl logs -f deployment/mongo-db -n ticket-prod         # MongoDB logs
```

### Debug a pod
```bash
kubectl describe pod <pod-name> -n ticket-prod     # Detailed pod info + events
kubectl exec -it <pod-name> -n ticket-prod -- sh   # Shell into a container
kubectl top pods -n ticket-prod                     # Memory/CPU usage (needs metrics-server)
```

### Deploy updates
```bash
kubectl rollout restart deployment/ticket-api -n ticket-prod     # Restart API
kubectl rollout restart deployment/ticket-admin -n ticket-prod   # Restart Frontend
kubectl rollout status deployment/ticket-api -n ticket-prod      # Watch rollout
```

### Nuclear options
```bash
kubectl delete -f k8s/                              # Delete everything
kubectl apply -f k8s/                               # Redeploy everything
kubectl delete namespace ticket-prod                 # Delete entire namespace
```

## 8. Troubleshooting Quick Reference

| Problem | Symptom | Fix |
|:---|:---|:---|
| **CrashLoopBackOff** | Pod keeps restarting | `kubectl logs <pod>` — check app errors |
| **ImagePullBackOff** | Can't pull Docker image | Check image name, registry login, `regcred` secret |
| **Pending** | Pod won't start | `kubectl describe pod` — likely not enough resources |
| **OOMKilled** | Pod killed by Linux OOM | Reduce resource limits, check swap is active |
| **SSL cert not ready** | HTTPS not working | Port 80 open in Security Group? DNS A records correct? |
| **Connection refused** | API/DB not reachable | Check service names, is the pod Running? |
| **502 Bad Gateway** | Ingress can't reach backend | Check pod readiness, service selector labels match |
| **Slow JVM startup** | API takes 60-90s to start | Normal on t3.micro — startup probe handles this |

For detailed troubleshooting, see [docs/04_troubleshooting.md](../docs/04_troubleshooting.md).
